# SPEC-002: Package manifest

Status: draft v0.2 · Phase 1 · Git repo + CI validation (no service runtime)

## Purpose

The trust root: the authoritative, human-governed statement of what packages
are authorized for build/publication, from which upstream sources, under
which policy profile and backend. All changes via PR. The publisher
(SPEC-006) enforces it; the dispatcher (SPEC-008) enumerates it.

## Scope / non-goals

- In scope: repo layout, entry schema, validation CI, governance states,
  publisher-facing checks, manifest_updated event.
- Non-goals: build results, current versions, artifact hashes (ledger's
  job); policy profile *contents* (SPEC-003); maintainer outreach workflows
  (SPEC-012 consumes states defined here).

## Repo layout

`seandavi/bioc-manifest` (its own repo, per ADR 0010):

```
packages/<name>.yaml         # one file per package, flat
schema/manifest.linkml.yaml  # source of truth for schema
CODEOWNERS                   # routes reviews by path/class
.github/workflows/validate.yml
```

PoC population: all current experiment data packages + workflow packages,
generated by a one-time importer from the existing Bioconductor manifests
(importer is a deliverable; its output PR is the founding governance act).

**Phase 1: see SPEC-014 §bioc-manifest** for the normative flat entry
format, `validate.yml` checks, and the publisher's manifest checks — all
three below are the phase-2 target, superseded for phase 1. In particular,
`git.bioconductor.org` is *the* upstream for every package (git.bioconductor
mirrors nothing; github.com/Bioconductor-mirror is the mirror, and is
missing 31 packages entirely — see issue #3's size audit). The phase-1
`git_url` is always `https://git.bioconductor.org/packages/<name>`; there
is no per-package host choice and no `source.host: bioc-git` variant to
encode, because every entry uses the same host.

## Target architecture (phase 2+): entry schema (per-package YAML)

```yaml
schema_version: "1"
name: curatedTCGAData
source:
  git_url: https://github.com/waldronlab/curatedTCGAData
  branch_map:
    devel: devel
    release: "RELEASE_{bioc_version}"   # template; literal allowed
maintainer:
  - name: …
    email: …
    github: …
streams:
  component: data-experiment        # data-experiment | workflows | software | data-annotation
  first_bioc_version: "1.10"
  last_bioc_version: null           # null = current
policy:
  profile: data-experiment          # must exist in SPEC-003 policy file
  overrides: {}                     # reviewed exceptions; schema per SPEC-003
backend: bioc-build                 # bioc-build | r-universe
status:
  state: active                     # active | limit_flagged | deprecated | archived
  since: "2016-04-12"
  reason: null                      # required non-null unless active
triage: issue_only                  # phase 3: auto_pr | issue_only | none
admission:
  pr: 1287
  approved_by: [gh-handle, …]
  date: "2016-03-30"
```

Per-package `source.git_url` choice (GitHub vs git.bioconductor.org) and
`backend` (bioc-build vs r-universe) return once this repo covers software
packages too; phase 1's population (data-experiment + workflows) is
git.bioconductor.org-only and bioc-build-only, so both collapse to
constants (see SPEC-014).

## Target architecture (phase 2+): validation CI (merge gate)

- Schema-valid against generated JSON Schema.
- `name` matches filename; unique.
- `git_url` reachable; resolved branch for current devel stream exists.
- `policy.profile` exists in the pinned SPEC-003 policy version.
- State transitions legal: active ↔ limit_flagged; {active,limit_flagged} →
  deprecated → archived. No resurrection from archived without new
  admission block.
- On merge to main: emit `manifest_updated` event (SPEC-009) with
  `{manifest_commit, changed_packages[], actor}`.

## Target architecture (phase 2+): publisher-facing contract

Publisher promotion checks (enumerated; SPEC-006 implements verbatim):

1. Staged DESCRIPTION `Package:` exists as `packages/<name>.yaml` at the
   manifest commit the publisher has pinned.
2. `status.state` ∈ {active, limit_flagged}.
3. Target stream's bioc_version ∈ [first_bioc_version, last_bioc_version].
4. `streams.component` equals target stream component.
5. Attestation source repo == `source.git_url`.
6. Built ref == resolved `branch_map` for target channel.
7. `backend` == bioc-build (external_publish path checks
   backend == r-universe instead).

Check 5 is weaker than it looks for a git.bioconductor.org source: the
attestation cryptographically binds the *build identity* (bioc-build's own
repo/workflow), not the fetched source repo — `source.git_url` consistency
is a publisher-recorded claim, not something GitHub attests to, because
git.bioconductor.org has no attestation mechanism of its own. **Accepted
risk for phase 1**: git.bioconductor.org is Bioconductor's own
infrastructure and is the canonical upstream (not a third party to
trust-extend to), so this is judged acceptable rather than requiring a
GitHub-mirror fallback (see SPEC-005 OQ-5.2).

Manifest consumption model: publisher and dispatcher read a checked-out
commit (updated by polling main), and record that commit sha in everything
they emit. No live-file reads.

## Acceptance criteria

- Importer produces valid entries for 100% of current experiment data +
  workflow packages; discrepancies vs existing manifests reported, not
  silently fixed.
- CI rejects each class of invalid fixture (bad state transition, dangling
  profile, template that resolves to a missing branch).
- `manifest_updated` events observed in archive for merges.

## Open questions

- OQ-2.1: Do workflow packages need per-package resource overrides at
  admission (some have very long vignettes)? Decide after PoC build data.
- ~~OQ-2.2: Encoding of git-hosting exceptions.~~ Resolved for phase 1:
  every entry uses git.bioconductor.org, so there is no exception to
  encode (see above). Reopens in phase 2 once GitHub-hosted software
  sources return as a per-package choice — affects attestation check #5;
  may still need a `source.host` variant with adjusted verification (see
  SPEC-005 OQ-5.2).
- OQ-2.3: Reviewer roster for PRs across the manifest (~459 packages at
  current experiment-data + workflow counts). `CODEOWNERS` routes reviews
  by path/class (phase 2+ repo layout), but *who* holds those paths is
  undecided — the importer PR is a good founding act, but ongoing review
  capacity has no owners yet. This, not the org (settled by ADR 0010,
  OQ-0.3), is what risks stalling manifest growth.
